01Introduction

WinUI 3 and Blazor are Microsoft's modern UI frameworks for .NET developers. Both use C# but target different platforms and use different markup languages.

🪟 WinUI 3

  • Native Windows desktop apps
  • XAML markup language
  • Successor to UWP/WPF XAML
  • Windows App SDK
  • Full Windows API access
  • Best performance on Windows

🔥 Blazor

  • Web apps with C# (no JavaScript)
  • Razor/HTML markup
  • Server-side or WebAssembly
  • Cross-platform (any browser)
  • Can be hosted anywhere
  • Blazor Hybrid for desktop

When to Use What?

RequirementBest ChoiceWhy
Windows-only desktop appWinUI 3Native performance, full Windows integration
Cross-platform web appBlazor WebAssemblyRuns in any browser, no server needed
Internal business appBlazor ServerFast initial load, real-time updates
Desktop + Web hybridBlazor Hybrid + MAUIShare UI code across platforms
High-performance desktopWinUI 3DirectX rendering, native controls
Existing web developersBlazorHTML/CSS skills transfer

04WinUI 3 XAML Basics

x:Bind vs Binding

💡 Use x:Bind

WinUI 3 uses {x:Bind} for compile-time checked bindings. It's faster than {Binding} and catches errors at build time.

x:Bind (Compiled) 
<!-- Default: OneTime (set once) -->
<TextBlock Text="{x:Bind Title}"/>

<!-- OneWay: Source → Target -->
<TextBlock Text="{x:Bind ViewModel.Status, Mode=OneWay}"/>

<!-- TwoWay: Source ↔ Target -->
<TextBox Text="{x:Bind ViewModel.Name, Mode=TwoWay}"/>

<!-- Bind to method -->
<Button Click="{x:Bind ViewModel.Save}"/>

<!-- Bind with function -->
<TextBlock Text="{x:Bind FormatDate(ViewModel.Date)}"/>
Code-Behind Property 
public sealed partial class MainPage : Page
{
    // x:Bind binds to code-behind properties
    public MainViewModel ViewModel { get; }
    public string Title => "My App";
    
    public MainPage()
    {
        ViewModel = new MainViewModel();
        this.InitializeComponent();
    }
    
    // Function for binding
    public string FormatDate(DateTime date)
    {
        return date.ToString("MMM dd, yyyy");
    }
}

06WinUI 3 Navigation

MainWindow with NavigationView 
<Window x:Class="MyApp.MainWindow">
    <NavigationView x:Name="NavView"
                    IsBackButtonVisible="Auto"
                    SelectionChanged="NavView_SelectionChanged"
                    BackRequested="NavView_BackRequested">
        
        <NavigationView.MenuItems>
            <NavigationViewItem Content="Home" Tag="HomePage">
                <NavigationViewItem.Icon>
                    <FontIcon Glyph=""/>
                </NavigationViewItem.Icon>
            </NavigationViewItem>
            <NavigationViewItem Content="Users" Tag="UsersPage"
                Icon="People"/>
        </NavigationView.MenuItems>
        
        <NavigationView.FooterMenuItems>
            <NavigationViewItem Content="Settings" Tag="SettingsPage"
                Icon="Setting"/>
        </NavigationView.FooterMenuItems>
        
        <Frame x:Name="ContentFrame"/>
    </NavigationView>
</Window>
Navigation Code-Behind 
public sealed partial class MainWindow : Window
{
    private readonly Dictionary<string, Type> _pages = new()
    {
        { "HomePage", typeof(HomePage) },
        { "UsersPage", typeof(UsersPage) },
        { "SettingsPage", typeof(SettingsPage) }
    };
    
    public MainWindow()
    {
        this.InitializeComponent();
        ContentFrame.Navigate(typeof(HomePage));
    }
    
    private void NavView_SelectionChanged(
        NavigationView sender, NavigationViewSelectionChangedEventArgs args)
    {
        if (args.SelectedItemContainer is NavigationViewItem item)
        {
            var tag = item.Tag.ToString();
            if (_pages.TryGetValue(tag!, out var pageType))
            {
                ContentFrame.Navigate(pageType);
            }
        }
    }
    
    private void NavView_BackRequested(
        NavigationView sender, NavigationViewBackRequestedEventArgs args)
    {
        if (ContentFrame.CanGoBack)
            ContentFrame.GoBack();
    }
}

ViewModel with Toolkit 
using CommunityToolkit.Mvvm.ComponentModel;
using CommunityToolkit.Mvvm.Input;

public partial class MainViewModel : ObservableObject
{
    // Auto-generates property with change notification
    [ObservableProperty]
    private string _name = "";
    
    [ObservableProperty]
    private bool _isLoading;
    
    [ObservableProperty]
    private ObservableCollection<User> _users = new();
    
    // Auto-generates ICommand
    [RelayCommand]
    private async Task LoadDataAsync()
    {
        IsLoading = true;
        var data = await _userService.GetAllAsync();
        Users = new(data);
        IsLoading = false;
    }
    
    // Command with CanExecute
    [RelayCommand(CanExecute = nameof(CanSave))]
    private void Save() { }
    
    private bool CanSave() => !string.IsNullOrEmpty(Name);
}

12Blazor Services & DI

Service Definition 
public interface IUserService
{
    Task<List<User>> GetAllAsync();
    Task<User?> GetByIdAsync(int id);
    Task CreateAsync(User user);
}

public class UserService : IUserService
{
    private readonly HttpClient _http;
    
    public UserService(HttpClient http)
    {
        _http = http;
    }
    
    public async Task<List<User>> GetAllAsync()
    {
        return await _http
            .GetFromJsonAsync<List<User>>("/api/users") 
            ?? new();
    }
}
Program.cs Registration 
var builder = WebApplication.CreateBuilder(args);

// Add services to DI container
builder.Services.AddScoped<IUserService, UserService>();
builder.Services.AddHttpClient<IUserService, UserService>(
    client => client.BaseAddress = new Uri("https://api.example.com")
);

// Blazor components
builder.Services.AddRazorComponents()
    .AddInteractiveServerComponents();

var app = builder.Build();
app.Run();

13Blazor Hybrid

Blazor Hybrid lets you run Blazor components in native desktop/mobile apps using .NET MAUI, WPF, or WinForms.

🔥 Best of Both Worlds

Use Blazor components inside WPF/WinUI apps. Share UI code between web and desktop!

WPF MainWindow.xaml 
<Window x:Class="MyHybridApp.MainWindow"
        xmlns:blazor="clr-namespace:Microsoft.AspNetCore.Components.WebView.Wpf;assembly=Microsoft.AspNetCore.Components.WebView.Wpf">
    
    <Grid>
        <!-- Blazor WebView hosts Blazor components -->
        <blazor:BlazorWebView HostPage="wwwroot/index.html"
                              Services="{DynamicResource services}">
            <blazor:BlazorWebView.RootComponents>
                <blazor:RootComponent 
                    Selector="#app"
                    ComponentType="{x:Type local:App}" />
            </blazor:BlazorWebView.RootComponents>
        </blazor:BlazorWebView>
    </Grid>

MainWindow.xaml.cs 
public partial class MainWindow : Window
{
    public MainWindow()
    {
        var services = new ServiceCollection();
        services.AddWpfBlazorWebView();
        
        // Register your services
        services.AddScoped<IUserService, UserService>();
        
        Resources.Add("services", 
            services.BuildServiceProvider());

    }

15Best Practices

🪟 WinUI 3 Best Practices

  • Use x:Bind over {Binding}
  • Use CommunityToolkit.Mvvm
  • Follow MVVM pattern strictly
  • Use ObservableCollection<T>
  • Handle async properly with commands
  • Use built-in theme resources
  • Test ViewModels with unit tests

🔥 Blazor Best Practices

  • Keep components small and focused
  • Use [Parameter] for component inputs
  • Use EventCallback for parent communication
  • Inject services via DI
  • Use StateHasChanged() sparingly
  • Use scoped CSS for component styles
  • Handle errors with ErrorBoundary

16WinUI WebView2 Shell

When WinUI embeds a Blazor Web App, the WinUI app becomes a lightweight shell and the web app is the real UI. Keep the shell stable and let the web app update independently.

    {
        InitializeComponent();
        WebView.NavigationCompleted += OnNavigationCompleted;
        WebView.Source = new Uri("https://app.company.local");
    }

    private void OnNavigationCompleted(object sender, CoreWebView2NavigationCompletedEventArgs e)
    {
        if (!e.IsSuccess) { ShowOfflineFallback(); }
    }
}

window.chrome.webview.postMessage({ type: "openSettings" });

// WinUI -> JS
WebView.CoreWebView2.WebMessageReceived += (_, args) =>

⚠️ Offline & Error Handling
  • Detect failed navigation and show a native fallback page.
  • Whitelist allowed domains to avoid unexpected navigation.
  • Decide how the shell behaves when the web app is down.

17Auth & Security

🪟 WinUI Shell

  • Prefer OS-backed identity (SSO, brokered auth)
  • Do not store long-lived tokens in the shell
  • Keep the shell stateless where possible

🔥 Blazor Web App

  • Use server-side auth with secure cookies
  • Protect all backend APIs (including Elsa)
  • Log out and token refresh must be predictable
💡 Recommended Boundary

The WinUI shell should never call Elsa APIs directly. The web app and its backend own workflow access and enforce permissions.
