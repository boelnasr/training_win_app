01Core Concepts

The Three Areas

Git manages your code in three main areas. Understanding how data flows between them is key.

Working Directory
Your actual files on disk
Staging Area
Changes ready to commit
Local Repository
Committed history (.git)

GitHub, GitLab, etc.

What is a Commit?

A commit is a snapshot of your project at a point in time. Each commit has a unique SHA hash, author, timestamp, and message.

📸 Commit History (Linear)
a1b2c3d C1
e4f5g6h C2
i7j8k9l C3
m0n1o2p C4
main HEAD

HEAD Pointer

HEAD is a pointer to the current branch/commit you're working on. It moves when you commit, checkout, or switch branches.

# Clone to specific folder
git clone url my-folder

Branch Commands

Terminal 
# List branches
git branch                    # Local branches
git branch -r                 # Remote branches
git branch -a                 # All branches

# Create new branch
git branch feature/login

# Switch to branch
git checkout feature/login
git switch feature/login     # Modern alternative

# Create and switch in one command

git branch -d feature/login  # Safe delete (merged only)

💡 Branch Naming Conventions
  • feature/ - New features (feature/user-auth)
  • bugfix/ - Bug fixes (bugfix/login-error)
  • hotfix/ - Urgent production fixes
  • release/ - Release preparation

05Merging

Merging combines changes from different branches. Git supports fast-forward and three-way merges.

Fast-Forward Merge

When the target branch has no new commits, Git just moves the pointer forward.

Merge Commands

Terminal 
# Merge branch into current branch
git checkout main
git merge feature/login

# Merge with commit message
git merge feature/login -m "Merge feature/login"

# Abort merge (if conflicts)
git merge --abort

# Force no fast-forward (always create merge commit)
git merge --no-ff feature/login

Handling Merge Conflicts

Conflict Markers

Your changes (current branch)

=======
Their changes (incoming branch)

>>>>>>> feature/login
Resolve & Complete 
# 1. Edit the conflicted files manually
# 2. Remove conflict markers, keep desired code
# 3. Stage resolved files
git add resolved-file.js

# 4. Complete the merge
git commit

06Rebasing

Rebasing moves your branch to start from a different point, creating a linear history.

🔀 Merge (preserves history)
C1
C2
C4
M
C3
C5

✓ Preserves complete history
✓ Safe for shared branches

📏 Rebase (linear history)
C1
C2
C4
C3'
C5'

✓ Clean, linear history
⚠️ Rewrites commits (new SHAs)

Rebase Commands

Terminal 
# Rebase current branch onto main
git checkout feature/login
git rebase main

# Interactive rebase (squash, reorder, edit commits)
git rebase -i HEAD~3  # Last 3 commits
git rebase -i main    # All commits since main

# Abort rebase
git rebase --abort

# Continue after resolving conflicts
git rebase --continue

Interactive Rebase Options

CommandDescription
pickKeep commit as-is
rewordKeep commit, edit message
editPause to amend commit
squashCombine with previous commit
fixupSquash, discard message
dropRemove commit entirely
⚠️ Golden Rule of Rebasing

Never rebase commits that have been pushed to a shared remote. Rebasing rewrites history, which causes problems for anyone who has based work on the original commits.

Remote Commands

Terminal 
# List remotes
git remote -v

# Add remote
git remote add origin https://github.com/user/repo.git

git remote remove origin

# Rename remote
git remote rename origin upstream

Fetch, Pull, Push

git fetch
Download changes from remote but don't merge. Updates remote-tracking branches.
git pull
Fetch + Merge in one command. Updates your branch with remote changes.
git push
Upload local commits to remote. Shares your work with others.
Terminal 
# Fetch all branches
git fetch
git fetch origin
git fetch --all

# Pull (fetch + merge)
git pull
git pull origin main

# Pull with rebase (cleaner history)
git pull --rebase

# Push to remote
git push
git push origin main

# Push new branch (set upstream)
git push -u origin feature/login

# Force push (use with caution!)
git push --force
git push --force-with-lease  # Safer

09Undoing Changes

Decision Tree: What to Undo?

Working Directory?
→
git checkout -- file or git restore file
Staged (added)?
→
git reset HEAD file or git restore --staged file
Last commit?
→
git commit --amend
Older commits?
→
git revert or git reset

Reset vs Revert

CommandWhat it doesSafe for shared branches?
git revert Creates new commit that undoes changes ✅ Yes - doesn't rewrite history
git reset --soft Move HEAD, keep changes staged ❌ No - rewrites history
git reset --mixed Move HEAD, keep changes unstaged (default) ❌ No - rewrites history
git reset --hard Move HEAD, discard all changes ❌ No - rewrites history, data loss!
Undo Commands 
# Discard changes in working directory
git checkout -- file.txt
git restore file.txt  # Modern

# Unstage file (keep changes)
git reset HEAD file.txt
git restore --staged file.txt  # Modern

# Undo last commit (keep changes staged)
git reset --soft HEAD~1

# Undo last commit (keep changes unstaged)
git reset HEAD~1

# Undo last commit (discard changes)
git reset --hard HEAD~1

# Revert a commit (safe for shared branches)
git revert abc123

# Revert multiple commits
git revert HEAD~3..HEAD

Stash Commands 
# Stash current changes
git stash
git stash push -m "Work in progress"

# Include untracked files
git stash -u

# List stashes
git stash list
# stash@{0}: WIP on main: abc123 Last commit message

# Apply most recent stash
git stash apply

# Apply specific stash
git stash apply stash@{2}

# Apply and remove from stash list
git stash pop

# Show stash contents
git stash show -p

# Drop a stash
git stash drop stash@{0}

# Clear all stashes
git stash clear

14Best Practices

💡 Commit Messages

Use conventional commits format:

  • feat: New feature
  • fix: Bug fix
  • docs: Documentation
  • style: Formatting
  • refactor: Code restructure
  • test: Tests
  • chore: Maintenance
Good Commit Messages 
# Good ✓
feat: add user authentication with OAuth
fix: resolve login timeout issue
docs: update API documentation

# Bad ✗
fixed stuff
changes
WIP

Golden Rules

✓ Do
• Commit often, push regularly
• Write clear commit messages
• Use branches for features
• Pull before push
• Review before merging
✗ Don't
• Force push to shared branches
• Commit sensitive data
• Rebase shared branches
• Ignore .gitignore
• Commit build artifacts
