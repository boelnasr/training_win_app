01The Problem Containers Solve

You build an app on your laptop. It works perfectly. Then you deploy it to a server and... it breaks.

😅 "But it works on my machine!"

This happens because environments differ:

💻
Your Laptop
Python 3.11
macOS
MySQL 8.0
≠
🖥️
Server
Python 3.9
Ubuntu
MySQL 5.7
✅ The Solution

Containers package your app WITH its entire environment — same Python version, same libraries, same everything. If it runs in a container on your laptop, it runs the same way everywhere.

06Working with Images

Images are read-only templates used to create containers. They're stored in registries like Docker Hub.

Image Commands 
# Pull image from Docker Hub
docker pull python:3.11
docker pull nginx:latest
docker pull postgres:15-alpine

# List local images
docker images
docker image ls

# Remove image
docker rmi python:3.11
docker image rm nginx

# Remove unused images
docker image prune

# Search Docker Hub
docker search redis

Image Naming Convention

📛 Image Name Format

[registry/]repository[:tag]

  • nginx → nginx:latest from Docker Hub
  • nginx:1.25 → specific version
  • python:3.11-slim → slim variant
  • gcr.io/my-project/app:v1 → Google Container Registry

07Working with Containers

Container Commands 
# Run a container
docker run nginx

# Run in background (detached)
docker run -d nginx

# Run with port mapping (host:container)
docker run -d -p 8080:80 nginx

# Run with name
docker run -d --name my-nginx -p 8080:80 nginx

# Run interactively
docker run -it ubuntu bash

# Run with environment variables
docker run -e MYSQL_ROOT_PASSWORD=secret mysql
Managing Containers 
# List running containers
docker ps

# List all containers (including stopped)
docker ps -a

# Stop container
docker stop my-nginx

# Start stopped container
docker start my-nginx

# Restart container
docker restart my-nginx

# Remove container
docker rm my-nginx

# Force remove running container
docker rm -f my-nginx

# View logs
docker logs my-nginx
docker logs -f my-nginx  # Follow logs

# Execute command in running container
docker exec -it my-nginx bash

Common Run Flags

FlagDescriptionExample

08Dockerfile

A Dockerfile is a text file with instructions to build a Docker image.

Dockerfile 
# Start from base image
FROM python:3.11-slim

# Set working directory
WORKDIR /app

# Copy requirements first (for caching)
COPY requirements.txt .

# Install dependencies
RUN pip install --no-cache-dir -r requirements.txt

# Copy application code
COPY . .

# Expose port
EXPOSE 8000

# Set environment variable
ENV PYTHONUNBUFFERED=1

# Command to run
CMD ["python", "app.py"]

Common Instructions

InstructionDescription
FROMBase image to start from
WORKDIRSet working directory
COPYCopy files from host to image
RUNExecute command during build
ENVSet environment variable
EXPOSEDocument exposed port
CMDDefault command when container runs
ENTRYPOINTMain executable (CMD becomes args)
ARGBuild-time variable
VOLUMECreate mount point

Build Commands 
# Build image from Dockerfile

docker build -f Dockerfile.prod -t my-app:prod .

docker build --build-arg VERSION=1.0 -t my-app .

# Tag image

# Push to Docker Hub
docker login

09Volumes (Persistent Data)

Containers are ephemeral — when removed, data is lost. Volumes persist data outside containers.

💾 Volume Types
Named Volumes
Managed by Docker
Best for production data
Bind Mounts
Host path → Container
Best for development
tmpfs
In memory only
For sensitive data
Volume Commands 
# Create named volume
docker volume create my-data

# List volumes
docker volume ls

# Use named volume
docker run -v my-data:/app/data my-app

# Bind mount (host path)
docker run -v $(pwd)/src:/app/src my-app
docker run -v ./data:/app/data my-app

# Read-only mount
docker run -v ./config:/app/config:ro my-app

# Remove volume
docker volume rm my-data

# Remove unused volumes
docker volume prune

10Networking

Docker creates virtual networks for container communication.

Network Commands 
# List networks
docker network ls

# Create custom network
docker network create my-network

# Run container on network
docker run -d --network my-network --name web nginx
docker run -d --network my-network --name db postgres

# Containers can reach each other by name!
# web can connect to db:5432

# Connect existing container to network
docker network connect my-network my-container

# Inspect network
docker network inspect my-network
💡 Container DNS

On a custom network, containers can reach each other using their container names as hostnames. No need for IP addresses!

11Docker Compose

Docker Compose manages multi-container applications with a single YAML file.

🐙 Multi-Container Application
🌐
web
:3000
⚙️
api
:8000
🗄️
db
:5432
⚡
redis
:6379
🔗 app-network (all services connected)
docker-compose.yml 
version: '3.8'

services:
  web:
    build: ./frontend
    ports:
      - "3000:3000"
    depends_on:
      - api
    environment:
      - API_URL=http://api:8000

  api:
    build: ./backend
    ports:
      - "8000:8000"
    depends_on:
      - db
      - redis
    environment:
      - DATABASE_URL=postgres://user:pass@db:5432/mydb
      - REDIS_URL=redis://redis:6379
    volumes:
      - ./backend:/app

  db:
    image: postgres:15-alpine
    environment:
      - POSTGRES_USER=user
      - POSTGRES_PASSWORD=pass
      - POSTGRES_DB=mydb
    volumes:
      - postgres-data:/var/lib/postgresql/data

  redis:
    image: redis:7-alpine

volumes:
  postgres-data:
Compose Commands 
# Start all services
docker compose up

# Start in background
docker compose up -d

# Build and start
docker compose up --build

# Stop all services
docker compose down

# Stop and remove volumes
docker compose down -v

# View logs
docker compose logs
docker compose logs -f api

# Execute command in service
docker compose exec api bash

# Scale service
docker compose up --scale api=3

13Best Practices

✅ Dockerfile Best Practices
  • Use official base images
  • Use specific tags, not :latest
  • Use -slim or -alpine variants for smaller images
  • Order commands from least to most frequently changing (caching)
  • Combine RUN commands to reduce layers
  • Use .dockerignore to exclude files
  • Don't run as root — use USER instruction
  • Use multi-stage builds for smaller production images

Multi-Stage Build Example

Dockerfile (Multi-Stage) 
# Build stage
FROM node:18 AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# Production stage
FROM nginx:alpine
COPY --from=builder /app/dist /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
⚠️ Security Tips
  • Never store secrets in images or Dockerfiles
  • Use environment variables or secrets management
  • Scan images for vulnerabilities
  • Keep base images updated
  • Don't run containers as root
