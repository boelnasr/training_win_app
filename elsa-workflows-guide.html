02Installation & Setup

Install NuGet Packages

Package Manager / CLI 
# Core Elsa packages
dotnet add package Elsa
dotnet add package Elsa.EntityFrameworkCore
dotnet add package Elsa.EntityFrameworkCore.Sqlite

# HTTP Activities
dotnet add package Elsa.Http

# Workflow Designer (Blazor)
dotnet add package Elsa.Studio.Host.Wasm
dotnet add package Elsa.Studio.Workflows

# Additional activities
dotnet add package Elsa.Scheduling
dotnet add package Elsa.Email
dotnet add package Elsa.Webhooks

Basic Configuration

Program.cs 
using Elsa.EntityFrameworkCore.Extensions;
using Elsa.EntityFrameworkCore.Modules.Management;
using Elsa.EntityFrameworkCore.Modules.Runtime;
using Elsa.Extensions;

var builder = WebApplication.CreateBuilder(args);

// Add Elsa services
builder.Services.AddElsa(elsa =>
{
    // Configure management persistence (workflow definitions)
    elsa.UseWorkflowManagement(management =>
    {
        management.UseEntityFrameworkCore(ef => 
            ef.UseSqlite("Data Source=elsa.db"));
    });
    
    // Configure runtime persistence (workflow instances)
    elsa.UseWorkflowRuntime(runtime =>
    {
        runtime.UseEntityFrameworkCore(ef => 
            ef.UseSqlite("Data Source=elsa.db"));
    });
    
    // Enable HTTP activities
    elsa.UseHttp();
    
    // Enable scheduling activities
    elsa.UseScheduling();
    
    // Register custom workflows
    elsa.AddWorkflow<MyFirstWorkflow>();
    
    // Enable C# expressions
    elsa.UseCSharp();
    
    // Enable JavaScript expressions
    elsa.UseJavaScript();
    
    // Expose REST API endpoints
    elsa.UseWorkflowsApi();
    
    // Enable Elsa Studio (designer)
    elsa.UseElsaStudio();
});

var app = builder.Build();

// Map Elsa API endpoints
app.UseWorkflowsApi();
app.UseElsaStudio();

app.Run();

03Core Concepts

📋 Workflow
A workflow is a series of activities that execute in a defined order. It can be long-running and persist state between executions.
⚡ Activity
The building block of workflows. Activities perform actions like sending emails, making HTTP requests, or custom business logic.
🔖 Bookmark
A marker that allows a workflow to pause and resume later. Used for long-running operations like waiting for external events.
📡 Signal
A named event that can trigger workflow execution or resume a suspended workflow. Enables event-driven architectures.
🎯 Trigger
Defines how a workflow starts — HTTP request, timer, signal, or programmatic invocation.
💾 Workflow Instance
A running (or completed) execution of a workflow definition. Contains state, variables, and execution history.

04Code-First Workflows

Define workflows directly in C# code for full type-safety and IDE support.

Simple Workflow

HelloWorldWorkflow.cs 
using Elsa.Workflows;
using Elsa.Workflows.Activities;
using Elsa.Workflows.Contracts;

public class HelloWorldWorkflow : WorkflowBase
{
    protected override void Build(IWorkflowBuilder builder)
    {
        builder.Root = new Sequence
        {
            Activities =
            {
                new WriteLine("Hello, World!"),
                new WriteLine("Welcome to Elsa Workflows!"),
                new WriteLine("Workflow completed.")
            }
        };
    }
}

Workflow with Variables

OrderWorkflow.cs 
public class OrderWorkflow : WorkflowBase
{
    protected override void Build(IWorkflowBuilder builder)
    {
        // Define workflow variables
        var orderId = builder.WithVariable<string>();
        var orderTotal = builder.WithVariable<decimal>();
        var isApproved = builder.WithVariable<bool>();

        builder.Root = new Sequence
        {
            Activities =
            {
                // Set initial values
                new SetVariable<string>
                {
                    Variable = orderId,
                    Value = new("ORD-001")
                },
                
                new SetVariable<decimal>
                {
                    Variable = orderTotal,
                    Value = new(250.00m)
                },
                
                // Conditional logic
                new If
                {
                    Condition = new(ctx => orderTotal.Get(ctx) > 100m),
                    Then = new Sequence
                    {
                        Activities =
                        {
                            new WriteLine("Order requires approval"),
                            new SetVariable<bool>
                            {
                                Variable = isApproved,
                                Value = new(false)
                            }
                        }
                    },
                    Else = new WriteLine("Order auto-approved")
                },
                
                // Use variable in output
                new WriteLine(ctx => 
                    $"Order {orderId.Get(ctx)} processed. Total: ${orderTotal.Get(ctx)}")
            }
        };
    }
}

builder.Services.AddElsa(elsa =>

06Custom Activities

Create your own activities to encapsulate business logic.

Simple Custom Activity

SendEmailActivity.cs 
using Elsa.Extensions;
using Elsa.Workflows;
using Elsa.Workflows.Attributes;
using Elsa.Workflows.Models;

[Activity("Custom", "Send Email", "Sends an email to the specified recipient")]
public class SendEmailActivity : CodeActivity
{
    // Input properties
    [Input(Description = "The recipient email address")]
    public Input<string> To { get; set; } = default!;
    
    [Input(Description = "The email subject")]
    public Input<string> Subject { get; set; } = default!;
    
    [Input(Description = "The email body")]
    public Input<string> Body { get; set; } = default!;
    
    // Output property
    [Output(Description = "The message ID of the sent email")]
    public Output<string> MessageId { get; set; } = default!;
    
    protected override void Execute(ActivityExecutionContext context)
    {
        // Get input values
        var to = To.Get(context);
        var subject = Subject.Get(context);
        var body = Body.Get(context);
        
        // Send email (your implementation)
        var messageId = EmailService.Send(to, subject, body);
        
        // Set output
        MessageId.Set(context, messageId);
    }
}

Async Activity with Dependency Injection

ProcessOrderActivity.cs 
[Activity("Business", "Process Order", "Processes an order through the system")]
public class ProcessOrderActivity : CodeActivity
{
    private readonly IOrderService _orderService;
    private readonly ILogger<ProcessOrderActivity> _logger;
    
    // Constructor injection
    public ProcessOrderActivity(
        IOrderService orderService,
        ILogger<ProcessOrderActivity> logger)
    {
        _orderService = orderService;
        _logger = logger;
    }
    
    [Input]
    public Input<string> OrderId { get; set; } = default!;
    
    [Output]
    public Output<OrderResult> Result { get; set; } = default!;
    
    protected override async ValueTask ExecuteAsync(ActivityExecutionContext context)
    {
        var orderId = OrderId.Get(context);
        
        _logger.LogInformation("Processing order {OrderId}", orderId);
        
        try
        {
            var result = await _orderService.ProcessAsync(orderId);
            Result.Set(context, result);
        }
        catch (Exception ex)
        {
            _logger.LogError(ex, "Failed to process order {OrderId}", orderId);
            throw;
        }
    }
}

Using Expressions in Activities

C# 
var name = builder.WithVariable<string>();
var count = builder.WithVariable<int>();

builder.Root = new Sequence
{
    Activities =
    {
        // Literal expression
        new SetVariable<string>
        {
            Variable = name,
            Value = new("Mohamed")
        },
        
        // C# delegate expression
        new WriteLine(ctx => $"Hello, {name.Get(ctx)}!"),
        
        // Computed expression
        new SetVariable<int>
        {
            Variable = count,
            Value = new(ctx => count.Get(ctx) + 1)
        },
        
        // JavaScript expression (requires UseJavaScript())
        new WriteLine
        {
            Text = new JavaScriptExpression<string>(
                "'Counter is now: ' + getVariable('count')")
        }
    }
};

09HTTP Activities

Build HTTP-triggered workflows and make outgoing HTTP requests.

HTTP Endpoint Trigger

HttpWorkflow.cs 
using Elsa.Http;

public class HttpTriggerWorkflow : WorkflowBase
{
    protected override void Build(IWorkflowBuilder builder)
    {
        var requestBody = builder.WithVariable<string>();
        
        builder.Root = new Sequence
        {
            Activities =
            {
                // HTTP trigger - workflow starts on POST /api/orders
                new HttpEndpoint
                {
                    Path = new("/api/orders"),
                    SupportedMethods = new(new[] { HttpMethods.Post }),
                    CanStartWorkflow = true,
                    ParsedContent = new(requestBody)
                },
                
                // Process the request
                new WriteLine(ctx => 
                    $"Received order: {requestBody.Get(ctx)}"),
                
                // Send response
                new WriteHttpResponse
                {
                    StatusCode = new(HttpStatusCode.OK),
                    ContentType = new("application/json"),
                    Content = new("{\"status\": \"received\"}")
                }
            }
        };
    }
}

Send HTTP Request

C# 
var response = builder.WithVariable<HttpResponseMessage>();
var responseBody = builder.WithVariable<string>();

new Sequence
{
    Activities =
    {
        // Make GET request
        new SendHttpRequest
        {
            Url = new("https://api.example.com/users/1"),
            Method = new(HttpMethods.Get),
            ParsedContent = new(responseBody)
        },
        
        // Make POST request with body
        new SendHttpRequest
        {
            Url = new("https://api.example.com/orders"),
            Method = new(HttpMethods.Post),
            ContentType = new("application/json"),

            {
                ["Authorization"] = "Bearer token123",
                ["X-Custom-Header"] = "value"

        },
        
        new WriteLine(ctx => $"Response: {responseBody.Get(ctx)}")
    }
}

12Bookmarks & Signals

Bookmarks allow workflows to pause and wait for external events. Signals provide a way to trigger or resume workflows.

Event-Driven Workflow

ApprovalWorkflow.cs 
public class ApprovalWorkflow : WorkflowBase
{
    protected override void Build(IWorkflowBuilder builder)
    {
        var approved = builder.WithVariable<bool>();
        
        builder.Root = new Sequence
        {
            Activities =
            {
                new WriteLine("Waiting for approval..."),
                
                // Wait for external signal
                new Event
                {
                    EventName = new("ApprovalReceived")
                },
                
                // Process approval result
                new If
                {
                    Condition = new(ctx => approved.Get(ctx)),
                    Then = new WriteLine("Approved!"),
                    Else = new WriteLine("Rejected.")
                }
            }
        };
    }
}

Trigger Signal from Code

ApprovalController.cs 
[ApiController]
[Route("api/[controller]")]
public class ApprovalController : ControllerBase
{
    private readonly IWorkflowRuntime _workflowRuntime;
    
    public ApprovalController(IWorkflowRuntime workflowRuntime)
    {
        _workflowRuntime = workflowRuntime;
    }
    
    [HttpPost("{workflowInstanceId}/approve")]
    public async Task<IActionResult> Approve(string workflowInstanceId)
    {
        // Trigger the event to resume the workflow
        await _workflowRuntime.TriggerEventAsync(
            eventName: "ApprovalReceived",
            workflowInstanceId: workflowInstanceId,
            input: new Dictionary<string, object>
            {
                ["approved"] = true
            });
        
        return Ok("Workflow resumed");
    }
}

public class WorkflowService
{
    private readonly IWorkflowRuntime _runtime;
    
    public WorkflowService(IWorkflowRuntime runtime)
    {
        _runtime = runtime;
    }
    
    public async Task<string> StartOrderWorkflow(OrderDto order)
    {
        // Start workflow by type
        var result = await _runtime.StartWorkflowAsync<OrderWorkflow>(

    {
        await _runtime.CancelWorkflowAsync(instanceId);
    }
}

OrderFulfillmentWorkflow.cs 
public class OrderFulfillmentWorkflow : WorkflowBase
{
    protected override void Build(IWorkflowBuilder builder)
    {
        var orderId = builder.WithVariable<string>();
        var paymentReceived = builder.WithVariable<bool>();
        
        builder.Root = new Sequence
        {
            Activities =
            {
                // Trigger: HTTP endpoint
                new HttpEndpoint
                {
                    Path = new("/api/orders/create"),
                    SupportedMethods = new(new[] { HttpMethods.Post }),
                    CanStartWorkflow = true
                },
                
                // Send confirmation
                new WriteHttpResponse
                {
                    StatusCode = new(HttpStatusCode.Accepted),
                    Content = new(ctx => 
                        $"{{\"orderId\": \"{orderId.Get(ctx)}\", \"status\": \"pending\"}}")
                },
                
                // Wait for payment (workflow suspends here)
                new Event
                {
                    EventName = new("PaymentReceived")
                },
                
                // Process the order
                new ProcessOrderActivity
                {
                    OrderId = new(orderId)
                },
                
                // Wait for shipment confirmation
                new Event
                {
                    EventName = new("ShipmentConfirmed")
                },
                
                // Send completion email
                new SendEmailActivity
                {
                    To = new("customer@email.com"),
                    Subject = new("Order Shipped!"),
                    Body = new(ctx => 
                        $"Your order {orderId.Get(ctx)} has been shipped!")
                },
                
                new Finish()
            }
        };
    }
}

18Best Practices

🎯 Single Responsibility
Keep workflows focused on one business process. Create separate workflows for distinct operations.
🔄 Idempotency
Design activities to be idempotent — safe to retry without side effects.
💾 Correlation
Use correlation IDs to link workflow instances to business entities (orders, users, etc.).
⚡ Keep Activities Small
Activities should do one thing. Complex logic belongs in services, not activities.
🔒 Error Handling
Always wrap external calls in try-catch. Consider retry policies for transient failures.
📊 Monitoring
Log workflow events. Use the built-in journal for debugging and auditing.
💡 Performance Tips
  • Use Parallel for independent activities that can run concurrently
  • Avoid storing large objects in workflow variables
  • Use appropriate persistence provider for your scale
  • Consider using distributed locking for high-concurrency scenarios
  • Clean up completed workflow instances periodically
⚠️ Common Pitfalls
  • Don't use non-serializable types in workflow variables
  • Avoid infinite loops in While activities
  • Don't call async methods synchronously in activities
  • Remember that workflow instances can span days — don't rely on in-memory state

19Security & Auth

🔐 Protect Workflow APIs
Secure all REST and management endpoints. Apply authentication and role-based access to workflow definition changes.
🧭 Separate Management & Runtime
Keep workflow definition management behind admin access. Runtime execution can be exposed more narrowly.
🧩 Tenancy & Data Isolation
If multi-tenant, scope workflows and instances per tenant and validate tenant IDs everywhere.
⚠️ Client Apps Should Not Call Elsa Directly

Expose workflows through your application API. Elsa endpoints should be internal or admin-only to avoid leaking workflow definitions.

20Ops & Monitoring

📈 Structured Logging
Include workflow ID, correlation ID, and activity name in all logs.
🧪 Health Checks
Monitor DB connectivity, queue/trigger health, and workflow runtime status.
📊 Workflow Journal
Use the built-in journal to diagnose failures and replay activity history.
💡 Alerting Signals
  • High count of suspended or faulted workflows
  • Retries exceeding thresholds
  • Long-running instances older than expected
